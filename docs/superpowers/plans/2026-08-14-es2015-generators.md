# ES2015 Generators and Iterator Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement ES2015 generator declarations, expressions, object/class methods, dynamic `%GeneratorFunction%`, `yield`, `yield*`, and exact iterator-facing resume semantics without retaining host JavaScript stack frames across suspension.

**Architecture:** Ordinary functions keep the existing synchronous evaluator. Generator calls perform parameter instantiation immediately, then return a Realm-owned `GeneratorObject` whose evaluator-owned `GeneratorExecution` contains a heap-resident stack of typed discriminated frames. Each `next`, `throw`, or `return` injects a Completion into an iterative continuation loop; yield-free subtrees may use the synchronous evaluator only after `containsYield` proves they cannot suspend.

**Tech Stack:** Plain ECMAScript modules, strict JSDoc checked by `tsc`, Acorn 8.18.0 configured for ES2015 scripts, the existing object/function/environment/completion/iterator runtime, portable repository test harnesses, pinned Test262 revision `b363f29d3c43c626dc852744ad64a0b48a003693`, Node, Chromium, and JavaScriptCore.

## Stable Layer-2 Interfaces

Later layers may rely on the following internal shapes and observable behavior:

```js
/**
 * @typedef {'suspendedStart' | 'suspendedYield' | 'executing' | 'completed'}
 *   GeneratorState
 *
 * @typedef {
 *   | { type: 'normal', value: unknown }
 *   | { type: 'throw', value: unknown }
 *   | { type: 'return', value: unknown }
 * } GeneratorResumeCompletion
 *
 * @typedef {
 *   | { type: 'yield', value: unknown }
 *   | { type: 'complete', completion: {
 *       type: 'normal' | 'return' | 'throw',
 *       value: unknown,
 *     } }
 * } GeneratorMachineResult
 *
 * @typedef {{
 *   resume(completion: GeneratorResumeCompletion): GeneratorMachineResult,
 * }} GeneratorContinuation
 */

class GeneratorObject extends EngineObject {
  state: GeneratorState;
  realm: Realm;
  continuation: GeneratorContinuation | null;
  resume(completion: GeneratorResumeCompletion): EngineObject;
}

class GeneratorExecution {
  frames: GeneratorFrame[];
  resume(completion: GeneratorResumeCompletion): GeneratorMachineResult;
}

containsYield(node: any): boolean

createGeneratorExecution(options: {
  functionObject: EngineFunction,
  body: any,
  context: EvaluationContext,
}): GeneratorExecution
```

The `GeneratorFrame` union is private but remains a typed discriminated union. Every member has a unique `kind`, a `phase` or program counter where necessary, and only the saved operands/references/environments/control state needed after suspension. No member stores a host closure as its continuation.

- [ ] **Step 7: Implement iterative `containsYield`**

Implement a worklist walk with a `WeakSet` for active/visited nodes. The traversal must:

```js
export function containsYield(node) {
  const pending = [node];
  const seen = new WeakSet();

  while (pending.length > 0) {
    const current = pending.pop();
    if (!current || typeof current !== 'object') continue;
    if (seen.has(current)) continue;
    seen.add(current);

    if (current.type === 'YieldExpression') return true;
    if (isNestedFunctionBoundary(current)) continue;
    if (current.type === 'MethodDefinition') {
      if (current.computed) pending.push(current.key);
      continue;
    }

    pushExecutedChildren(current, pending);
  }

  return false;
}
```

`pushExecutedChildren` must enumerate explicit evaluator-consumed edges rather than generic object properties. A class expression contributes heritage and computed names, but no method body. A function declaration/expression/arrow contributes nothing when it is nested beneath the queried node. The root generator body is queried by passing its body/list rather than the function node itself.

```js
   * @param {Realm} realm
```

- [ ] **Step 5: Implement the iterative machine and typed frame channels**

Create:

```js
export class GeneratorExecution {
  constructor({ functionObject, body, context }) {
    this.functionObject = functionObject;
    this.realm = functionObject.realm;
    this.frames = [createStatementListFrame(body, context)];
    this.input = null;
    this.output = null;
  }

  resume(completion) {
    this.input = completion;
    for (;;) {
      const frame = this.frames[this.frames.length - 1];
      if (frame === undefined) return completeFromMachine(this.output);
      const action = dispatchGeneratorFrame(this, frame);
```
